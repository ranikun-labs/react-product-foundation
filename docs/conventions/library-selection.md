# 외부 라이브러리 선택·확장 가이드

> 목적: 외부 라이브러리를 쓰다가 "스타일이 안 먹어서 DOM을 강제로 바꾸는" 상황을 만들지 않는다.
> 이 문서는 RPF 자체 규약이다. 특정 라이브러리를 도입하라는 결정이 아니며, 현재 RPF·두 제품의 의존성에 이 문서가 언급하는 헤드리스 라이브러리는 포함되어 있지 않다.

## 1. 확장 순서 (위에서부터, 해결되면 멈춘다)

1. **공식 옵션**: props·옵션·테마·CSS 변수로 되는가.
2. **Composition / Slot**: 공식 확장 지점(`asChild`, slot, render prop, 자식 조합)으로 되는가.
3. **최소 Wrapper**: 우리 컴포넌트가 원본을 감싸 기본값만 정한다. 원본 props를 그대로 통과시킨다.
4. **소스 수정**: 복사 방식(예: shadcn류)으로 소유한 코드를 고친다. 변경 이유와 원본 대비 차이를 파일 머리에 남긴다.
5. **교체**: 더 적합한 라이브러리로 바꾼다. 호출부가 Wrapper 뒤에 있으면 비용이 작다.
6. **자체 구현**: 위가 모두 안 될 때만. 접근성(키보드·포커스·ARIA)을 직접 책임진다.

단계를 건너뛸 때는 PR 본문에 "왜 이전 단계가 안 됐는가"를 적는다.

## 2. 금지

| 금지                                                                                            | 이유                                                                                        |
| ----------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| 라이브러리 **Private API / 내부 클래스명** 의존 (예: 생성된 해시 클래스, 문서에 없는 내부 속성) | 마이너 업데이트에도 깨진다. 공식 확장 지점이 없으면 3~5단계로 간다                          |
| `!important`로 스타일 덮어쓰기                                                                  | 우선순위 전쟁을 만들고 다크 모드·상태 스타일에서 다시 깨진다. 토큰/변수 또는 variant로 푼다 |
| 라이브러리가 렌더한 **DOM을 직접 변경** (`querySelector` 후 속성·스타일·노드 조작)              | React 재렌더와 충돌하고 접근성 속성이 깨진다                                                |

## 3. 직접 만들지 않고 검증된 라이브러리를 우선 쓰는 컴포넌트

**Dialog, Select, Popover, DatePicker, Chart**는 포커스 트랩, 포털, 충돌 감지, 키보드 탐색, 시간대·로케일, 스크린리더 등
직접 구현 시 실패모드가 많다. 먼저 검증된 라이브러리를 평가한다. 기본 `<dialog>`·`<select>`로 충분하면 그것이 가장 싸다.

### Headless 라이브러리(예: Radix 등) 비교 기준

특정 제품을 추천하지 않는다. 후보는 아래 기준으로 같은 표에 놓고 고른다.

| 기준                          | 확인 방법                                                        |
| ----------------------------- | ---------------------------------------------------------------- |
| 접근성                        | WAI-ARIA 패턴 준수, 키보드·포커스 복원 동작을 실제 화면에서 확인 |
| 스타일링 자유도               | 무스타일(unstyled)인가, 공식 variant/데이터 속성 제공 여부       |
| 확장 지점                     | Composition/Slot(`asChild` 등) 지원 여부 (1~2단계가 가능한가)    |
| React 19 / SSR·prerender 호환 | 공식 지원 버전, 서버 렌더 시 `window` 접근 여부                  |
| 번들 크기                     | 사용 컴포넌트만 트리쉐이킹되는가(실제 빌드 크기 측정)            |
| 유지보수 상태                 | 최근 릴리즈, 이슈 응답, 메인테이너 수                            |
| 라이선스                      | 상업 사용 가능 여부                                              |
| Capacitor(WebView)            | 포털·스크롤 잠금·소프트 키보드 동작을 모바일 WebView에서 확인    |
| 교체 비용                     | Wrapper 뒤에 숨길 수 있는가                                      |

Chart와 DatePicker는 Headless 범주가 아닐 수 있다. 같은 표에서 번들 크기와 로케일 지원을 특히 본다.

## 4. 새 런타임 의존성 추가 체크

- 이 문서의 1~2단계로 해결되지 않는다는 근거가 있는가.
- 정확한 버전 고정과 `pnpm-lock.yaml` 반영, `pnpm verify` 통과.
- 번들 크기 증가 수치를 PR에 기록한다(미측정이면 `NOT_RUN`).
- 디자인 시스템의 토큰·컴포넌트와 겹치면 정본은 [`ranikun-labs/design-system`](https://github.com/ranikun-labs/design-system)을 따른다. 이 저장소에 복제하지 않는다.

# 라우팅·인증 가드·API 호출·환경 변수 규약

> 두 제품(Finance, Carelog)의 실제 코드(2026-11 시점)에서 **공통인 부분만 규약**으로, 갈라진 부분은 **선택지**로 적는다.
> RPF는 인증·API 클라이언트·상태관리 라이브러리를 **기본 탑재하지 않는다.** 아래 선택지는 제품이 고르는 항목이며, 어느 쪽도 표준이 아니다.

## 1. 라우팅

### 규약 (두 제품과 RPF 공통)

- 경로 정의의 유일한 원본은 `src/constants/routes.ts`다. 컴포넌트·테스트에 경로 문자열을 하드코딩하지 않는다.
- 공개 웹은 `/:locale/*`, 앱은 `/app/*`(`APP_BASE`)로 나눈다. 루트 `/`는 기본 로케일 redirect 전용이다.
- 지원 로케일은 `SUPPORTED_LOCALES`가 단일 원본이고, 판별은 `isSupportedLocale`만 쓴다.
- 파라미터가 들어가는 경로는 `build*Path()` 함수로 만들고 값은 `encodeURIComponent`로 감싼다.
- 중첩 라우트의 상대 경로는 `toRelativeUnder(base, path)`로 얻는다(직접 문자열을 자르지 않는다).
- 공개 경로를 추가하면 `src/prerender/manifest.ts`와 prerender 검증 스크립트도 함께 갱신한다.

### 선택지: 인증 라우트 (제품마다 다름)

| 제품    | 인증 라우트                                 | 특징                                                                          |
| ------- | ------------------------------------------- | ----------------------------------------------------------------------------- |
| Finance | `/auth` 단일 진입(`AUTH_ROUTE_PATHS.entry`) | `/app/*` 셸 밖에 둬서 하단 내비게이션이 없다. 제공자(Provider) 중립 진입 화면 |
| Carelog | `/auth/{entry,login,signup}` (`AUTH_BASE`)  | 인증 상태에 따라 `Navigate`로 이동                                            |

RPF에는 인증 라우트가 없다. 제품이 필요할 때 위 중 하나를 고르거나 다른 구조를 쓴다. 단 경로 정의는 반드시 `routes.ts`에 둔다.

## 2. 인증 가드

### 규약

- 보호 대상 라우트는 **라우트 경계 한 곳**에서 막는다. 개별 페이지가 각자 로그인 여부를 확인하지 않는다.
- 가드는 "확인 중 / 비로그인 / 로그인 / 오류"를 구분해 렌더한다. 확인 중에 보호 화면을 잠깐 보여주거나 곧바로 로그인 화면으로 보내지 않는다.
- 로그인 후 이동 경로는 한 함수로 모은다(Carelog `resolvePostAuthPath`).
- 토큰은 로그·URL·테스트 fixture에 평문으로 남기지 않는다.

### 선택지: 가드 구현 방식 (두 제품이 다르다)

| 방식                                                              | 사례                                                                               | 트레이드오프                                                             |
| ----------------------------------------------------------------- | ---------------------------------------------------------------------------------- | ------------------------------------------------------------------------ |
| 라우트 경계 컴포넌트 + 상태 switch + `Navigate`                   | Carelog `ProtectedAppBoundary`(`AuthProvider` Context + 상태기계 + port + adapter) | 상태가 명시적이고 테스트하기 쉽다. 파일·개념이 많아 작은 제품에는 무겁다 |
| 라우트별 "로그인 필요" 표면 + 외부 스토어(`useSyncExternalStore`) | Finance `AuthRequiredSurface` + reference auth 세션                                | 가벼우나 가드가 라우트별로 흩어질 수 있다                                |

추천(참고용): 보호 라우트가 3개 이상이거나 토큰 갱신이 필요하면 **경계 컴포넌트 방식**, 그 미만이고 로그인 화면만 필요하면 Finance 방식에서 시작한다.
이 문서는 둘 중 하나를 표준으로 정하지 않는다. 공통 인증 상태기계는 RPF에 승격하지 않는다(근거: 평가 문서 3장 "승격하지 않는 것").

## 3. API 호출

### 규약

- 네트워크 호출은 화면 컴포넌트에서 `fetch`를 직접 흩뿌리지 않고 **한 모듈(포트/클라이언트)** 뒤에 둔다. 테스트에서 교체 가능해야 한다.
- 오류는 호출자가 분기할 수 있는 모양(종류 코드 또는 타입이 있는 Error)으로 던진다. 메시지 문자열 파싱으로 분기하지 않는다.
- 운영(`import.meta.env.PROD`)에서는 `https:`가 아닌 베이스 URL을 거부한다(Carelog `authPort.ts`).
- 응답은 사용 전에 모양을 확인한다. 서버 응답을 그대로 신뢰해 UI 상태로 넣지 않는다.
- 요청에 Secret을 하드코딩하지 않는다. 브라우저 번들에 들어가는 `VITE_*` 값은 공개된다고 가정한다.

### 선택지

| 항목                   | 사례                                                                                                                                                                                                                        |
| ---------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| HTTP 클라이언트        | Carelog는 자체 `createCarelogHttpClient`(401 재시도, 세션 provider, 응답 envelope 처리)를 쓴다. 이는 Carelog API 계약에 묶여 있어 일반화하지 않았다. Finance는 도메인별 포트(Read/Create Port) 뒤에 `fetch` 구현을 주입한다 |
| 데이터 패칭 라이브러리 | 두 제품 모두 사용하지 않는다. 도입은 제품이 정한다(`library-selection.md` 순서 적용)                                                                                                                                        |

RPF는 **공통 API Client를 제공하지 않는다.** 두 제품에 같은 패턴이 없기 때문이다.

## 4. 환경 변수

### 규약

- 브라우저에 노출할 값만 `VITE_` 접두사를 쓰며, `src/vite-env.d.ts`의 `ImportMetaEnv`에 **타입을 선언**한다(전부 optional `string`).
- 읽는 코드는 한 곳에서 정규화한다(공백 trim, 빈 문자열은 미설정 처리). 화면 곳곳에서 `import.meta.env`를 직접 읽지 않는다.
- 불리언 플래그는 `=== 'true'`로만 켠다. 미설정은 꺼짐이다.
- 위험한 플래그는 `PROD`에서 무시한다(Finance는 reference auth를 운영에서 켜지 못하게 `PROD` 인자를 함께 검사한다).
- Secret(토큰·키)은 `VITE_`로 두지 않는다. `.env*` 파일은 커밋하지 않는다.

### 선택지: 변수 체계

| 제품    | 변수                          | 용도                               |
| ------- | ----------------------------- | ---------------------------------- |
| Finance | `VITE_FINANCE_*_ENABLED` 계열 | 기능 플래그                        |
| Carelog | `VITE_CARELOG_API_BASE_URL`   | API 베이스 URL (+ 운영 https 강제) |

변수 이름은 제품 접두사를 쓴다. 공통 변수 체계는 정하지 않는다.
